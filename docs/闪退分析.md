# 闪退分析（Bug 差在哪）

## 现象

v1 单机版（`KFNT_Offline_v0.17.8.apk`）真机安装成功，启动后进入**加载页面即自动闪退**（crash to desktop，非卡死）。

- 引擎已起（能看到加载页 = Unity/Mono/补丁后的 DLL 都加载成功了）
- 崩溃点在加载步骤机（LoadingNode）执行期间
- **闪退而非卡死** → 大概率 Java 层或 native 层硬崩，而非 C# 异常（C# 异常 Unity 只记日志不闪退）

## 闪退点之前的执行路径（v1）

```
StepInitSDK: LGSDKManager.InitManager()
  → new GameObject("UnityLGSDKPlugin") → Awake()
    → startSdk()   → LGSDKCore.Init() → 反射调 ByteDance.Union.LGSDKDevKit.Init + LGAccountService.Init
                     → LGAndroidCoreInit → AndroidJavaObject("com.ss.union.game.sdk.core.init.callback.LGSdkInitCallback")
                     → Java 层 init()   ← 【第一嫌疑：首个 Java 桥调用】
    → startAd/startAccount/startAnti/startRealName/startPush()
Patch B 位置：InitSDK 末尾（initialized 门控）→ 崩溃若在前面则补丁B未执行
StepLogin（Patch A 位置）：loginStart → accountLogin → guestLogin → Java NormalLogin
```

## 嫌疑清单（按可能性排序）

### S1. LG SDK（ByteDance Union LightGame）Java 层 init 崩溃 ★★★
加载页第一步就是它的 Java 桥 init。签名变更后 SDK 内部状态异常、依赖服务缺失、
或设备/渠道校验失败都可能直接崩。DEX 已反编译（dex1-4），`com.ss.union.game.sdk.core` 全量可查。
- 已注意到：`PrivacyPolicyFragment.java:204 System.exit(0)`（隐私拒绝路径，自动流程不应触发，低概率）

### S2. native 看门狗（加固自保）★★
包内可疑组件：`libdaemon.so` / `libsupervisor.so`（名字即看门狗）、`libsgcore.so`（安全内核）、
`cex.so`、`libEncryptorP.so`；mono so 本体被重度魔改（符号全剥、build-id note 被篡改、
5 个乱码导出 + `get_seconds()`）。若存在"延迟 N 秒校验签名/完整性 → exit"的定时器，
时间点恰好落在加载页。DEX 里有 `killProcess/System.exit/getPackageInfo/signatures/checkSignature` 组合
（已核实 SignUtils 是穿山甲插件验签、push 的是进程清理——**未找到宿主自校验的调用方**，此方向证据不足）。

### S3. 补丁 A 的连带反应 ★
失败链新路径：`accountLoginFailed() → register() → registerEnd() → status=Login → requestServerLogin()`
→ `loginObject.requestWithUserId(null, accountData.accountId)`——此时 **accountData 可能为 null → NRE**。
但 NRE 属 C# 异常，Unity 会记日志继续跑（且 loginEndEvent 在 afterLoginEnd 已触发），
最多导致卡 StepLogin，不解释"闪退"。⇒ 可加补丁C防护，但不是闪退主因。

### S4. 与补丁无关、原版就崩 ★
原版在死服务器/无 GMS 环境下的固有问题（如 Firebase/Facebook 某回调空指针在 Java 层未捕获）。
**判别法**：出一个"零补丁仅重签名"的对比包测试。

## 已排除

| 嫌疑 | 排除依据 |
|---|---|
| gameprotect 反篡改 | 守护库 `libgp.so` 不在 APK 内（服务器下发制），服务器死了它就是死的 |
| SignUtils 宿主自校验 | 只用于穿山甲插件包验签（宿主 vs 插件包），重签后两边一致仍通过 |
| push killProcess | 推送多进程清理逻辑，7秒内杀5次才触发 |
| 热更/游戏服务器 | 本构建热更关闭、无游戏服务器 URL，全程无依赖 |

## 下一步诊断（决定性）

1. **logcat 抓堆栈**（雷电9已装好）：`adb logcat` 过滤 `FATAL EXCEPTION / AndroidRuntime / libc / DEBUG`，
   一次定位是 Java 崩、native 崩（tombstone）还是 Unity abort。
2. 对比包隔离：零补丁仅重签名版 + 只含补丁A版 + 只含补丁B版，三选一对照。
3. 若 native 崩：Ghidra headless 分析 libdaemon/libsupervisor/mono so 的 exit 调用链。

## 预案（按堆栈对应的修法）

| 崩溃归属 | 修法 |
|---|---|
| LG SDK Java init | smali 层让 init 直接走 fail 回调（apktool 反编 dex 改 smali）；或 C# 层让 startSdk() 直接 return（IL 补丁C，LGSDKCore.Init 调用点 NOP） |
| native 看门狗 | Ghidra 定位 exit 调用点 → patch so 字节（同类原位补丁思路） |
| 补丁A连带 | 补丁C：`requestServerLogin()` 增加空 accountData 防护或直接旁路 |
| 原版固有 | 按堆栈具体修 |
